# Password Managers

With the [Mailflare Worker](worker-mode.md), password managers can create an alias for you right
when you sign up somewhere: Bitwarden's username generator, for example, creates a new alias and
fills it in. The Worker speaks the same API as addy.io and SimpleLogin, which these apps already
support, so no plugin is needed.

## Create a key

1. Open your Worker's app and go to **API keys** (on a phone: **Settings → API keys**).
2. Click **Create key** and choose:
    - **Name**: where you use the key, for example "Bitwarden".
    - **Destination**: the inbox the new aliases forward to.
    - **Default domain**: for apps that don't send a domain (SimpleLogin clients). Bitwarden's
      addy.io setting has its own.
    - **Alias format and prefix**: as in the app. With a prefix, aliases are named after the
      website you're signing up on, for example `example_k3x9q2m7@your.domain`.
3. Copy the key. It's shown only once; if you lose it, delete it and create a new one.

A key can only create aliases. It can't list, change or delete them, and it can't do anything
else in your account. Delete a key when you stop using it: aliases it created stay.

## Bitwarden

In Bitwarden (browser extension, desktop or mobile app, or web vault):

1. Open the **Generator** and choose **Username**.
2. Under **Type**, choose **Forwarded email alias**.
3. Set **Service** to **addy.io**, and enter:
    - **Email domain**: one of your Worker's domains, for example `your.domain`.
    - **API access token**: your key (`mf_…`).
    - **Self-host server URL**: your Worker's address followed by `/api/addy`, for example
      `https://mailflare.example.workers.dev/api/addy`.
4. Click **Generate**. The alias appears in your Mailflare app with Bitwarden's note, such as
   "Website: example.com. Generated by Bitwarden."

The app shows these values after creating a key, each with a copy button.

## Other apps

Apps that support SimpleLogin with a custom server can use the same key with the server URL
`https://<your worker>/api/simplelogin`. Aliases go to the key's default domain, or the first
domain available to you.

Apps that support addy.io with a custom server use `https://<your worker>/api/addy`.

## Accounts

On a Worker with accounts, each account creates its own keys. Aliases created with a key belong to
that account and count toward its limits, on the domains the account may use. Suspending an account
stops its keys.
